# Clarity pass: review screens and wording

Starting commit `8a7612c` (main). One bounded pass: the Requirements → Review → document path, the shared staff views, and a wording pass on follow-ups, help, adviser and portal copy. No lending rule, threshold, readiness result, permission, answer-freshness rule, audit record or stored value was changed.

## What changed

- **One explanation helper** (`src/lib/staff/explain.ts`). Each supported check family (manual confirmation, lender tracking, presence, period, freshness, signature, page count, form revision, value agreement, ownership, party name, relationships such as lease coverage) has its own sentence and next action. Unknown check types fall back to the check's own condition. Failed checks read "Not met"; unknown ones read "Not confirmed yet" (manual: "Not recorded"; tracking: its saved state).
- **Requirements**: the open check is shown in the row, with any saved note, the preparation effect and one primary action. Counts say which open rows stop preparation and which are later lender work. Manual checks record "Completed / Not completed yet" with an explanation that it records the review, not a yes/no answer. Tracking starts at "Not recorded yet" rather than defaulting to "Not started". The table stacks on narrow screens.
- **Review**: the specific explanation replaces "A person has to decide". The primary action goes to the control that resolves the item. Manual items list "Documents on file" without signature metadata. Value items show each value as recorded on the item (never today's value) and its source. The "reads declared transaction terms" line appears only when a check actually reads the profile, and names what it reads. Dismiss/waive are under "Other options", with their real effects. The detail panel is keyed by item, so an unsaved reason never carries to another item or owner. Closed items are described from their stored message.
- **Document view**: links carry `finding`/`row` keys that are resolved against this deal on the server. The page shows what was open, whether this document can answer it, and a working way back. Return paths are accepted only for this deal's Review or Requirements. "Edit document details" is separate from viewing.
- **Priority**: badges and the filter read "Top/High/Normal priority"; stored severities are unchanged. Preparation effect comes from `rowPreparationEffect`/`findingStopsPreparation`, now exported from `readiness.ts` and used by the readiness calculation itself (same logic, moved into named functions).
- **Follow-ups**: manual checks and tracking become questions, not document requests; citizenship handling goes to the lender; signature issues ask specifically. An answers-only message is headed "Information needed".
- **Wording**: US spelling (license, aging, authorization); help rewritten as a workflow, saying the demo uses prepared sample readings in mock mode; "One small thing", "carry on with your day", "Move the file forward", "Most consequential first" and "Inspect …" removed; portal instructions use the task's own periods; the adviser "not ready" sentence says what is outstanding; later lender work shows "Status not recorded yet" or "Recorded, not yet received".
