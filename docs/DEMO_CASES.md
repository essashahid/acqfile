The existing acquisition profile and pack 8 are retained. Purchase $1,000,000 + other uses $100,000 = $1,100,000; loan $900,000 + buyer cash $150,000 + seller financing $50,000 = $1,100,000. ## Prepare once, then switch without resetting

Use an existing **sample-only** workspace and staff membership. Configure `REAL_DATA_MODE=false`, `ACQFILE_SAMPLE_MODE=true`, `LLM_PROVIDER=mock`, `JOB_DRIVER=inline`, and local sample storage/auth. Set `DEMO_CASE_WORKSPACE_ID` to that workspace's UUID and `DEMO_CASE_ACTOR_ID` to an existing admin/reviewer member's UUID. The command does not create credentials or grant membership. Do not point it at a real-data environment.

```sh
pnpm demo:generate
pnpm demo:cases seed
pnpm dev
```

Sign in through the existing staff login. The **Demo case** dropdown on `/staff/deals` opens the current seeded deal. It writes nothing. Each case has a short situation sentence and the actual reading mode. Staff permissions and workspace scope are checked again on the server. Adviser/recipient accounts cannot invoke the selector. No public role switcher or token directory is added.

Initial evidence is uploaded through normal intake. Human checks, uncertain readings, corrections and exports remain undone. D05 starts with a normal staff reopening of the consulting reading after noticing the two conflicting drafts; it makes no new decision about which is right. D06 has its required historical $900,000 answer recorded through the normal answer action, against the original evidence key; its amended rounds are not uploaded. D07 alone uses the existing processing-boundary injection adapter for one local job, recorded as failed in the real UI. No completion helper, direct acceptance writes or `demo:b-ready` is used for these cases.

The generated corpus stores one shared baseline and a few variants, with manifests for each case. Authored prepared candidates are consumed only inside the explicit mock classification/extraction boundary; evaluation, questions, permissions, readiness and exports use the usual application paths. Actual PDF/AcroForm/DOCX/XLSX parsing still runs. The existing Deal A/B/C corpora and accepted baselines are unchanged.

Corrections are in `fixtures/demo/generated/Dxx/corrections/` and `round-2.zip` (plus D06 `round-3.zip`). Do not upload a correction ZIP until the script reaches that step. Ordered PNG pages for the photo exercise are stored separately. Generated sample pages contain synthetic notices. D02's six-page mixed packet has an agreement on original pages 1–2 and supplemental personal statements on 3–4 and 5–6. Full official six-page Form 413s are supplied separately; supplements do not silently replace the official forms.

To open adviser view, use the existing `/deals/{dealId}` navigation with an authorized account. Create/reissue **one** person's link using **Manage this person's link and reminder**. Copy it when shown, and open it in a separate browser profile. Never copy all tokens into a shared document. No email is sent by AcqFile.

## Reset exactly one case

```sh
pnpm demo:cases reset D04
```

This requires an existing marked case in the configured workspace and an authorized staff actor. It refuses other names, unmarked targets, missing markers and real-data mode. Source hashes must match the generated manifest. Concurrent seed/reset commands for that case are serialized. Existing links are revoked, the old generation is archived, and a fresh initial generation is created. Old evidence and immutable exports remain stored for audit; this is **not a purge**. Other cases and deals are untouched. An interrupted initial seed is reported explicitly; inspect it, then reset only that named case. A normal seed rerun preserves a finished seed and subsequent operator work.
